
v0.0.0 - 2021-01-12

This is the initial commit of a project written several years ago, used for some small deployments, and untouched for a couple of years. It recently has been tested against Ubuntu 20.04, go 1.15.6, the Ubuntu repo version of MySQL and Cassandra 3.11.9. It has not yet been tested against the latest versions of the vendored golang dependencies.


v0.0.3 - 2024-06-24

Updated jackc/pgx from v4 to v5


v0.0.4 - 2026-11-17

qsess: cookies and tokens are now bound to the store that issued them, so stores that share encryption keys no
longer accept each other's values. Each back-end constructor sets the new Store.Name to where the store keeps its
sessions (its table name or key prefix), and Name is authenticated into every value. The new Store.Binding is
authenticated along with Name, for an application that needs to bind values to a deployment or to one copy of a
database. The new Store.AcceptUnbound, set by default, keeps accepting values issued by earlier versions, so an
upgrade invalidates nothing; clear it once no such value can still be presented. An earlier version cannot read a
value issued by this one, so a downgrade invalidates every value issued since the upgrade.


v0.0.5 - 2026-11-17

qsess: added Store.ConsumeTokenSession, which reads a session and deletes it in one atomic operation, so that of
several concurrent presentations of a single-use token exactly one succeeds. It needs the new optional Consumer
back-end interface, which the PostgreSQL, goleveldb and in-memory back ends implement; for MySQL and Cassandra,
which do not, it returns an error. Session.Delete no longer returns nil when the database delete fails and there is
nothing to delete from the client, as was the case for a token store with no DeleteToken function.


v0.0.6 - 2026-11-18

qsess: six defects found in a review of the session code.

mapStore.Get deleted expired sessions from its maps while holding only a read lock, which aborts the process with
"concurrent map writes" when expired values are presented concurrently; it now deletes under the write lock,
re-checking the expiration.

The goleveldb DeleteByUserID matched user ids by prefix, so deleting the sessions of user "a" also deleted those of
user "ab", and an empty user id deleted every session in the store; it now matches exactly, with no change to the
stored key format.

The goleveldb pruner deleted any key in its expiration index range whose length was wrong, which destroyed the
records of a second store whose prefix extended this one's, and any application data stored under the same prefix;
it now leaves alone, and logs, a key it cannot identify as its own.

Two Saves of one session within the same second deleted the goleveldb expiration index record that the second Save
had just written, leaking the session; the old index key is now deleted only when it differs from the new one.

The goleveldb pruner stopped at the first unexpired record, but the index is keyed by a little-endian expiration
time and so is not ordered by expiration, which could leave expired sessions unreclaimed indefinitely; it now
carries on past them. Records already orphaned in existing stores are not repaired.

Session.Delete and Session.Token no longer panic on a session that was never Saved: Token returns an error, and
Delete deletes the client's copy and skips the database.

Breaking change, and only for an application that supplies its own Encrypt and Decrypt: Decrypt now receives the
base64-decoded bytes, which is what Encrypt returned, so a symmetric pair round-trips. Such an application must
remove any base64 decode of its own, after which the values it issued earlier are accepted again. The value format
and the default AES-GCM path are unaffected.


v0.0.7 - 2026-11-25

The go directive is now go 1.25, raised from go 1.15, so a program that imports this module needs Go 1.25 or later,
and go get of this release raises the importing module's directive to 1.25, with the language and GODEBUG changes
that brings. In return, the go command can prune the module graph instead of walking the requirements of every back
end and of the examples. go.mod also lists the indirect requirements that pruning needs, among them newer versions
of golang.org/x/sys and github.com/rogpeppe/go-internal.

qsess: errors can be told apart. Each error from getting, saving or deleting a session now matches one of four new
values, ErrNoCredential, ErrInvalidCredential, ErrBackEnd and ErrApplication, for an application to answer with
401, 401, 503 and 500. An error from one of the application's own functions keeps any of these classes it matches.
Error texts have changed, so match errors with errors.Is and errors.As, which now also reach a driver's error.

qsess: an application's own back end must now report a missing or expired session with an error that matches the
new ErrNotFound, or the miss is reported as ErrBackEnd; qstest's shared tests now check a back end for this and the
rest of what this release requires. An application's GetToken must return an empty token and no error for a
request that carries none.

qsess: a session that is gone stays gone. Session.Save of an expired session now fails, as for a deleted one,
except on Cassandra, whose Save, an upsert, still recreates any session that is gone. Session.Delete now reports a
failed database delete even when it has deleted the client's copy, and deleting a session that is already gone is
not a failure.

qsldb: a Save that overlapped a logout, a revocation or a token redemption could bring the session back. Each
goleveldb store now makes its changes to sessions under a lock of its own, so two stores on one database must not
share a prefix, and a store refuses any session that another store issued, even one whose value AcceptUnbound lets
through. Sessions the race already left out of DeleteByUserID's reach are not repaired. DeleteByUserID now reports
a failure that can leave a session valid, where it always returned nil. It and the pruner no longer delete keys
that only look like their own, and the pruner no longer panics on a malformed record.

qsess: the in-memory store now deletes expired sessions in a goroutine of its own, so a program that discards map
stores, such as a test, must send on Store.PruneKill to free each one.

qsess: the documentation now says what was always required: an application's own Store.Encrypt and Store.Decrypt
must be authenticated encryption, like the default AES-GCM, or, on most back ends, a client can forge another
session's cookie or token.

qsess: a MySQL Save that changes nothing, as a second Save within a second can, no longer fails. Smaller defects
across qsess and its back ends are fixed too.
